## 升级与恢复

1. 停止持有目标数据库的全部 Joy 运行时和 worker，确认进程退出后再做文件备份。WAL 可能含已提交数据，不能只复制仍在运行的 SQLite 主文件；无法停机时应使用 SQLite 感知的备份方式。
2. 保留升级前完整 home、配置及对应二进制版本的快照，限制访问权限。快照可能包含对话、OAuth 令牌和凭据，不应进入代码仓库或报告。重要的外部工作区文件需另行备份。
3. 在可丢弃副本上测试新二进制，关闭执行、委派、hooks 和外部服务。确认迁移、启动、记忆视图、任务检查及关闭，再开展已授权工作。不能让两个运行时持有同一规范数据库。
4. 未知效果需要人工核对：检查操作与外部系统，通过已有控制接口记录决定，必要时给出新指令。恢复数据库不会撤销外部效果，还可能丢失回执，不能盲目重试。
5. 返回旧版本前先停止新进程并保留当前状态。将匹配旧二进制的升级前快照恢复到另一个 home，不要让旧二进制直接使用迁移后的数据库，也不要手工删除新列或表。恢复任务前先核对快照之后的效果与交付。

尚无经过测试的自动 schema 降级、远端效果事务回滚，或恢复快照含最新授权的保证。现有恢复测试针对升级后运行时崩溃，不是旧版本回退的端到端测试。新领取标记不能识别历史无标记领取；记忆删除/更正也不等于历史与备份全面脱敏。

## 验证边界

[生产代码验证](../evals/results/harness-validation-2026-11-14-projection.json)：Rust 935、前端 113、Python 14、确定性 70、回放 5 项，以及四套端到端和五场景进程恢复均通过。该记录早于后续仅修改评测器的研究试验；研究示例另有七项测试、Clippy 与真实模型记录。研究发布工具没有修改生产运行时，它是显式启用评测器中的受限 MCP 适配器。

[实施报告](harness-implementation-report-2026-11-14.zh.md)列出剩余质量与集成工作。发布前仍需审查混合差异和实际候选版本；检查通过不等于发布授权，也不证明个人助理质量。
