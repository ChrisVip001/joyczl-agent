# 分阶段研究与实际隔日继续

[English](long-research-study-2026-11-14.md) | 简体中文

这项显式运行的验证研究一个实际决策：Joy 如何组合持久化、重试、人工授权和远端核对，安全承接隔日工作。主线是任务交付。评测者从三家发布方选取六份官方资料片段，覆盖活动幂等、工作流回放、重试策略、持久化计时器、本地数据库原子性及 HTTP 方法语义。模型读取留存片段；不据此声称已验证自主检索或连续数小时推理。

[预先登记的验收条件](../evals/results/long-research-preregistration-2026-11-14.json)早于付费执行。首阶段生成含六条可追溯结论、决策矩阵、限制和故障测试的 `draft.json`，随后通过已有 `task/wait` 等待输入，暂不交付最终报告。单独的 `review` 阶段使用同一授权模型的新会话，关闭全部工具并保留完整批评。这是上下文分离，不等同于独立人工或不同模型评审；评审非空不能代表语义质量合格。

`resume` 阶段要求真实经过至少 86,400 秒，以新进程重新打开同一状态库，核实任务仍暂停后，由人工触发评审输入，并重复提交同一事件检查重复确认。原任务继续读取草稿及评审，生成 `report.md`。保留任务状态、运行身份、操作回执、来源引用与产物原始字节。最终还须逐条核对结论、范围、反例、修改情况和决策可用性；文件存在不足以证明质量。

不操作日历、邮件或其他外部账号。用户提出继续时才由宿主发送隔日输入，不安排自动续做。24 小时限制属于评测器，不代表生产调度器新增保证。禁止修改时间戳、来源清单或任务状态凑通过；失败记录保留，独立重测使用新目录。

## 复现

工作目录必须是持久化、隔离的绝对路径，预先放置 `sources.json`，包含六个不同来源 ID、HTTPS URL 和资料片段，并保留原始页面、抓取时间和摘要。不得使用用户平时的 Joy 状态库作为工作目录。配置目录只用于解析授权模型，不向工作目录复制凭证。

```sh
cargo run -p joyczl-eval --example live_reliability --manifest-path joy-rs/Cargo.toml -- \
  --home /path/to/configured/profile --suite research-long --phase start \
  --work-home /absolute/path/to/isolated/study --budget-cny 1.05 --out /path/to/new-start.json
```

下一次改为 `--phase review`、新输出路径和剩余总预算内的限额。真实等待满 24 小时后，人工再运行 `--phase resume`，使用另一个新输出路径。每次付费前复核官方价格和[累计预算](../evals/results/live-budget-2026-11-14.json)；单次限额不代表重新获得 ¥10。现有评测套件不会隐式增加请求。前置检查失败发生在解析付费提供方之前。即使用例失败也保留完整输出，不能仅用退出码判断通过。
