# Harness 升级实施记录

[English](harness-upgrade.md) | 简体中文

用于持续落实 2026-11-12 架构评估。这是接续清单，不代表报告已经全部实现。保留 Rust 运行时、SQLite、人类控制授权与自动生成协议。

## 已实现并有回归测试

- 工具批次执行前记录意图；持久化失败则停止，未知结果的批次暂停核对，不自动重放。
- checkpoint 与接续保存稳定轮次身份，按累计水位原子更新任务/run 总额；记账失败停止任务。旧断点若已有记账且缺少轮次身份，先等待核对。
- 按 checkpoint 关联的 run 找回任务；新建与恢复共用记账、预算、验收和目标驱动器，恢复后可在已授权轮数内继续推进。
- 后台作业使用跨进程随机身份；先写意图再启动进程，台账失败阻止启动。
- 作业先收集输出再公布完成；限时等待读取管道，无法读完时明确标记。作业绑定确切 task/run，结果、任务事件与已请求投递记录原子提交。
- 持久保存确切作业依赖，正常完成后接续已授权任务，重启后可恢复；人工暂停、取消优先，中断或被停止的作业等待核对，竞争唤醒只领取一次。
- 原子领取后续指令，结果落盘前保留原记录；重启时保留未知结果并写对话提示；并发领取不会重复取走同一条。
- 中文技能使用不同相邻汉字双字组合匹配，保留英文和显式调用限制。
- 快速聊天带上本会话近期对话与 SOUL，不带入其他会话内容。
- MCP 断线后重建连接，但不自动重放远端结果未知的调用。
- 长期目标跨轮延续操作编号，避免后续操作被错误去重。
- 过短工具预览优先保留可用的完整输出路径。
- 已配置的完成通知先持久化、再发送，失败后周期性及重启重试，确认成功才删除；批准提示不重放，网络错误不泄露 webhook 凭据。

## 仍需完成，按顺序推进

1. 扩展观察、记账、最终落盘之间的故障注入覆盖。崩溃前未记录的活动时长仍是近似值，不是硬实时预算。
2. 恢复结构化计划与交接状态。新建与恢复已共用验收/目标驱动器；普通聊天自动接续仍在驱动器之前单独处理。
3. 扩展后台作业之外的持久等待，并补齐目标和定时任务的结果到通知之间的提交窗口。后台作业已原子生成完成事件并支持持久唤醒。
4. 增加逐操作状态、外部状态核对、安全重放元数据与服务端幂等键。批次 checkpoint 只是保守保护，不是外部操作恰好执行一次。
5. 加强版本化交付物证据与领域回执；区分产出和验证完成，避免旧 run 的工具成功次数满足新任务验收。
6. 后台任务拥有独立执行上下文，统一人格与进度投影；当前快答只有有限近期上下文，尚无完整长期关系连续性。
7. 将结构化任务交接、约束与未知操作独立于滚动摘要保存；维护个人记忆更正与删除语义。
8. 原生 Responses 已支持文本、图片、函数工具、SSE 和本地加密接续。继续补模型能力/推理力度配置与真实模型验证；托管工具、WebSocket 引导、API 异步工具暂不支持。
9. 添加故障注入与固定预算真实模型评测，报告完成率、虚假完成率、重复副作用、恢复率及成本；确定性检查不能证明真实事务可靠。
